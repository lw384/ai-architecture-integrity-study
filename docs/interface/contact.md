# Contact API

> **Resource**: `/api/contacts`
>
> **Implementation source**: `baseline/backend/src/module/contact/*`
>
> **Status**: this document describes the **current backend implementation**

---

## 1. Scope

The current backend exposes Contact endpoints under the global `/api` prefix.

Implemented:

- create
- list with pagination, filtering, and search
- get by id
- partial update via `POST /contacts/:id`
- soft delete via `DELETE /contacts/:id`

## 2. Entity Schema

`src/module/contact/contact.entity.ts`

| Field             | Type                        | Constraints               | Mutability           | Notes                                              |
| ----------------- | --------------------------- | ------------------------- | -------------------- | -------------------------------------------------- |
| `id`              | `string` (UUID)             | generated by DB           | read-only            | Primary key                                        |
| `companyId`       | `string` (UUID)             | required FK               | read-write on create | Update path rejects changes to a different company |
| `name`            | `string`                    | required, max 255         | read-write           | Contact name                                       |
| `email`           | `string \| null`            | nullable column, max 255  | read-write           | Create DTO currently requires a valid email field  |
| `phone`           | `string \| null`            | nullable column, max 50   | read-write           | Create DTO currently requires this field           |
| `role`            | `string \| null`            | nullable column, max 100  | read-write           | Optional in create DTO                             |
| `lastContactedAt` | `string (ISO 8601) \| null` | nullable timestamp column | read-write           | Stored column                                      |
| `createdAt`       | `string (ISO 8601)`         | generated by DB           | read-only            | Timestamp                                          |
| `updatedAt`       | `string (ISO 8601)`         | generated by DB           | read-only            | Timestamp                                          |
| `deletedAt`       | `string (ISO 8601) \| null` | soft-delete timestamp     | internal             | `select: false`, normally not returned             |

Relations:

- `company: CompanyEntity` via `@ManyToOne`
- ORM relation uses `onDelete: 'CASCADE'`

## 4. DTOs

### 4.1 `CreateContactDto`

`src/module/contact/dto/create.dto.ts`

```typescript
class CreateContactDto {
  companyId: string;
  name: string;
  email: string;
  phone: string;
  role?: string;
  lastContactedAt?: Date;
}
```

Validation actually enforced by decorators:

- `companyId`: required UUID v4
- `name`: required string, max 255
- `email`: required valid email
- `phone`: required string, max 50
- `role`: optional string, max 100
- `lastContactedAt`: optional pass-through field

Important mismatch between entity and DTO:

- the entity allows `email` and `phone` to be nullable
- the create DTO currently requires both fields

### 4.2 `UpdateContactDto`

`src/module/contact/dto/update.dto.ts`

```typescript
class UpdateContactDto extends PartialType(CreateContactDto) {}
```

All create fields become optional during update, including:

- `companyId`
- `email`
- `phone`
- `lastContactedAt`

Update-specific behavior implemented in the service:

- if `companyId` is present and **different** from the existing value, the
  service throws `422`
- if `companyId` is present and **equal** to the existing value, it is deleted
  from the DTO and the update proceeds

### 4.3 `ContactListQueryDto`

`src/module/contact/dto/query.dto.ts`

| Field             | Type                | Default     | Behavior                                                    |
| ----------------- | ------------------- | ----------- | ----------------------------------------------------------- |
| `companyId`       | UUID v4             | none        | Exact filter                                                |
| `sort`            | `name \| createdAt` | `createdAt` | Applied as `contact.<field>`                                |
| `order`           | `asc \| desc`       | `desc`      | Converted to upper case for TypeORM                         |
| `pageSize`        | integer             | `10`        | Must be `1..100`                                            |
| `page`            | integer             | `1`         | Must be `>= 1`                                              |
| `q`               | string              | none        | ILIKE search across `name`, `email`, `phone`, `role`        |
| `role`            | string              | none        | Exact filter                                                |
| `lastContactedAt` | Date                | none        | Present in DTO but currently unused by repository filtering |

Computed accessors used by the repository:

- `offset = (page - 1) * pageSize`
- `limit = pageSize`

## 5. Endpoint Details

### 5.1 `POST /contacts`

Creates a contact.

**Request example**:

```http
POST /api/contacts
Content-Type: application/json

{
  "companyId": "a3f8c1e2-1234-5678-9abc-def012345678",
  "name": "Alice Chen",
  "email": "alice@acme.com",
  "phone": "+1-555-0100",
  "role": "VP Sales"
}
```

**Response** (`201`):

```json
{
  "id": "b4e9d2f3-1234-5678-9abc-def012345678",
  "companyId": "a3f8c1e2-1234-5678-9abc-def012345678",
  "name": "Alice Chen",
  "email": "alice@acme.com",
  "phone": "+1-555-0100",
  "role": "VP Sales",
  "lastContactedAt": null,
  "createdAt": "2026-07-03T10:30:00.000Z",
  "updatedAt": "2026-07-03T10:30:00.000Z"
}
```

Behavior:

- the controller returns the saved entity directly
- the service first calls `companyService.getCompanyById(dto.companyId)`
- if the company lookup fails, the request returns `404`

Possible errors:

- `400` for DTO validation failures
- `404` if the referenced company does not exist

### 5.2 `GET /contacts`

Lists contacts with filtering and search.

**Query parameters**:

| Param       | Type                  | Default     | Notes                          |
| ----------- | --------------------- | ----------- | ------------------------------ |
| `companyId` | UUID v4               | none        | Exact filter                   |
| `sort`      | `name` or `createdAt` | `createdAt` | Invalid value returns `400`    |
| `order`     | `asc` or `desc`       | `desc`      | Invalid value returns `400`    |
| `pageSize`  | integer               | `10`        | `1..100`                       |
| `page`      | integer               | `1`         | `>= 1`                         |
| `q`         | string                | none        | Case-insensitive partial match |
| `role`      | string                | none        | Exact filter                   |

Repository behavior:

- sorting defaults to `contact.createdAt DESC`
- `q` searches `name`, `email`, `phone`, and `role` with `ILIKE`
- `companyId` and `role` are exact filters
- `lastContactedAt` from the query DTO is ignored by the repository

**Response** (`200`):

```json
{
  "items": [
    {
      "id": "b4e9d2f3-1234-5678-9abc-def012345678",
      "companyId": "a3f8c1e2-1234-5678-9abc-def012345678",
      "name": "Alice Chen",
      "email": "alice@acme.com",
      "phone": "+1-555-0100",
      "role": "VP Sales",
      "lastContactedAt": null,
      "createdAt": "2026-07-03T10:30:00.000Z",
      "updatedAt": "2026-07-03T10:30:00.000Z"
    }
  ],
  "total": 1,
  "page": 1,
  "pageSize": 10,
  "totalPages": 1
}
```

### 5.3 `GET /contacts/:id`

Gets one contact by id.

**Behavior**:

- `ParseUUIDPipe({ version: '4' })` validates the path param
- invalid UUID returns `400` before service execution
- missing record returns `404`

Missing-record response shape after the exception filter:

```json
{
  "success": false,
  "code": 404,
  "message": "Contact with ID <id> not found",
  "timestamp": "2026-07-19T00:00:00.000Z",
  "path": "/api/contacts/<id>"
}
```

### 5.4 `POST /contacts/:id`

Partially updates a contact.

**Request example**:

```http
POST /api/contacts/b4e9d2f3-1234-5678-9abc-def012345678
Content-Type: application/json

{
  "role": "Chief Revenue Officer"
}
```

**Response** (`201`): the updated `ContactEntity`.

Behavior:

- the service loads the contact first
- if `companyId` is included and differs from the stored value, it throws
  `UnprocessableEntityException`
- if `companyId` is included and matches the stored value, it is ignored
- the remaining DTO fields are merged and saved

**Different-company error** (`422`):

```json
{
  "success": false,
  "code": 422,
  "message": "The companyId field cannot be updated after creation.",
  "timestamp": "2026-07-19T00:00:00.000Z",
  "path": "/api/contacts/<id>"
}
```

Other errors:

- `400` for invalid UUID or DTO validation failures
- `404` when the contact does not exist

### 5.5 `DELETE /contacts/:id`

Soft-deletes a contact.

**Request**:

```json
​http
DELETE /api/contacts/b4e9d2f3-1234-5678-9abc-def012345678
```

**Response** (`204 No Content`): empty body.

Behavior:

- `ParseUUIDPipe({ version: '4' })` validates the path param
- invalid UUID returns `400`
- service calls `contactRepository.softDelete(id)`, which writes the
  `deletedAt` column and preserves the row
- if the contact does not exist (or is already soft-deleted, since the
  entity has `select: false` on `deletedAt`, TypeORM will not return
  already-deleted rows), returns `404`
- DELETE is idempotent in effect: repeating the request on the same id
  returns `404` after the first successful delete

**Missing-record response**: standard envelope with `code: 404`, message
`"Contact with ID <id> not found"`.

Related-record note: after T1, Deals may reference a Contact via
`contactId`. Deleting the Contact does **not** cascade to Deals — the
There is no additional service-layer detach logic in the current baseline;
the delete implementation only soft-deletes the contact row itself.

## 6. Error Envelope

All `HttpException` responses are transformed by `src/common/filter/http-exception.filter.ts`:

```json
{
  "success": false,
  "code": 400,
  "message": "first validation or exception message",
  "timestamp": "2026-07-19T00:00:00.000Z",
  "path": "/api/contacts"
}
```

Notes:

- `code` is numeric HTTP status
- validation errors surface only the first message
- service-level domain payloads such as `{ code: 'ENTITY_NOT_FOUND', ... }`
  are not preserved in the final response envelope except through `message`

  @Post()

## 8. Behavior Summary

- create requires `companyId`, `name`, `email`, and `phone`
- list supports `companyId`, `role`, and free-text `q` filtering
- update uses `POST`, not `PATCH`
- update returns `201` because it uses the default `POST` status code
- `companyId` is only rejected when changing to a different value
- `lastContactedAt` is a stored field, not a derived projection
- contact delete is implemented as a soft delete
