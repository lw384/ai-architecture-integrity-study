# Company API

> **Resource**: `/api/companies`
>
> **Implementation source**: `baseline/backend/src/module/company/*`
>
> **Status**: this document describes the **current backend implementation**, not the target v2 spec.

---

## 1. Scope

The current backend exposes Company endpoints under the global `/api` prefix set
in `src/main.ts`. There is **no `/api/v1` prefix**.

The Company module currently provides:

- create
- list with simple pagination
- get by id
- partial update via `POST /companies/:id`
- soft delete via `DELETE /companies/:id`

The implementation is intentionally simple and differs from the richer T1 spec
in several places:

- `lastContactedAt` is a **stored column**, not a derived field
- `status` uses enum values `'0' | '1' | '2'`, not `'active' | 'inactive'`
- `industry` exists in the entity and query filter
- soft-delete metadata exists on the entity via `deletedAt`

## 2. Entity Schema

`src/module/company/company.entity.ts`

| Field | Type | Constraints | Mutability | Notes |
|---|---|---|---|---|
| `id` | `string` (UUID) | generated by DB | read-only | Primary key |
| `name` | `string` | required, max 255 | read-write | Company name |
| `email` | `string \| null` | optional, max 255, email format | read-write | Company email |
| `phone` | `string \| null` | optional, max 50 | read-write | Free-form phone |
| `website` | `string \| null` | optional, max 255, URL when non-empty | read-write | Empty string is accepted by DTO validation |
| `status` | `'1' \| '0' \| '2'` | enum | read-write | `'1' = ACTIVE`, `'0' = INACTIVE`, `'2' = PENDING` |
| `industry` | `'TECHNOLOGY' \| 'FINANCE' \| 'MANUFACTURING' \| 'RETAIL' \| 'OTHER' \| null` | enum | read-write | Optional |
| `lastContactedAt` | `string (ISO 8601) \| null` | nullable timestamp column | read-write | Persisted column, not computed |
| `createdAt` | `string (ISO 8601)` | generated by DB | read-only | Timestamp |
| `updatedAt` | `string (ISO 8601)` | generated by DB | read-only | Timestamp |
| `deletedAt` | `string (ISO 8601) \| null` | soft-delete timestamp | internal | `select: false`, normally not returned |

Relations:

- `contacts: ContactEntity[]` via `@OneToMany`

## 3. Endpoints

| Method | Path | Summary | Success | Notes |
|---|---|---|---|---|
| `POST` | `/companies` | Create a company | `201` | Returns a success wrapper, not the created entity |
| `GET` | `/companies` | List companies | `200` | Supports pagination and simple filters |
| `GET` | `/companies/:id` | Get one company | `200` | Returns the raw entity |
| `POST` | `/companies/:id` | Partial update | `201` | Returns the updated entity because `POST` uses the Nest default |
| `DELETE` | `/companies/:id` | Soft-delete a company | `204` | Returns `409` when active contacts still exist |

## 4. DTOs

### 4.1 `CreateCompanyDto`

`src/module/company/dto/create.dto.ts`

```typescript
class CreateCompanyDto {
  name: string;
  email?: string;
  phone?: string;
  website?: string;
  status?: CompanyStatus;
  industry?: Industry;
  lastContactedAt?: Date;
}
```

Validation actually enforced by decorators:

- `name`: required string, max 255
- `email`: optional, must be email, max 255
- `phone`: optional string, max 50
- `website`: optional; validated as URL only when value is not `''`
- `status`: optional enum of `CompanyStatus`
- `industry`: optional enum of `Industry`
- `lastContactedAt`: optional and effectively pass-through in the DTO

Default values:

- `status` defaults to `'2'` (`PENDING`) at the entity layer

### 4.2 `UpdateCompanyDto`

`src/module/company/dto/update.dto.ts`

```typescript
class UpdateCompanyDto extends PartialType(CreateCompanyDto) {}
```

All create fields become optional during update, including:

- `status`
- `industry`
- `lastContactedAt`

There is **no empty-update guard** in the current implementation.

## 5. Endpoint Details

### 5.1 `POST /companies`

Creates a company.

**Request example**:

```http
POST /api/companies
Content-Type: application/json

{
  "name": "Acme Corp",
  "email": "info@acme.com",
  "status": "1",
  "industry": "TECHNOLOGY"
}
```

**Response** (`201`):

```json
{
  "success": true,
  "message": "Company created successfully",
  "companyId": "a3f8c1e2-1234-5678-9abc-def012345678"
}
```

Notes:

- The controller relies on Nest's default `POST` status code, so create returns `201`.
- The response does **not** include the created entity body.
- No `Location` header is set.

**Validation / error behavior**:

- DTO validation failures return `400`
- Error responses are wrapped by `HttpExceptionFilter` as:

```json
{
  "success": false,
  "code": 400,
  "message": "...",
  "timestamp": "2026-07-19T00:00:00.000Z",
  "path": "/api/companies"
}
```

### 5.2 `GET /companies`

Lists companies using repository pagination.

**Query parameters**:

| Param | Type | Default | Notes |
|---|---|---|---|
| `page` | integer-ish string | `1` | Invalid or `< 1` falls back to `1` |
| `pageSize` | integer-ish string | `10` | Invalid or `< 1` falls back to `10`; max effective size `100` |
| `status` | string | none | Applied only if it matches a `CompanyStatus` enum value |
| `industry` | string | none | Applied only if it matches an `Industry` enum value |

Important behavior:

- Sorting is fixed to `createdAt DESC`
- Invalid `status` / `industry` values are ignored, not rejected
- Invalid `page` / `pageSize` values fall back to defaults, not `400`

**Response** (`200`):

```json
{
  "items": [
    {
      "id": "a3f8c1e2-1234-5678-9abc-def012345678",
      "name": "Acme Corp",
      "email": "info@acme.com",
      "phone": null,
      "website": null,
      "status": "1",
      "industry": "TECHNOLOGY",
      "lastContactedAt": null,
      "createdAt": "2026-07-03T10:30:00.000Z",
      "updatedAt": "2026-07-03T10:30:00.000Z"
    }
  ],
  "page": 1,
  "pageSize": 10,
  "total": 1,
  "totalPages": 1
}
```

### 5.3 `GET /companies/:id`

Gets one company by id.

**Request**:

```http
GET /api/companies/a3f8c1e2-1234-5678-9abc-def012345678
```

**Response** (`200`): raw `CompanyEntity` JSON.

**Error behavior**:

- There is **no UUID pipe** on this route
- A malformed id is treated the same as any missing record if no row is found
- Missing company returns `404` with message:

```json
{
  "success": false,
  "code": 404,
  "message": "Company with ID <id> not found",
  "timestamp": "2026-07-19T00:00:00.000Z",
  "path": "/api/companies/<id>"
}
```

### 5.4 `POST /companies/:id`

Partially updates a company.

**Request example**:

```http
POST /api/companies/a3f8c1e2-1234-5678-9abc-def012345678
Content-Type: application/json

{
  "website": "https://acme.example",
  "status": "0"
}
```

**Response** (`201`): the updated `CompanyEntity`.

Behavior:

- The service loads the entity first with `getCompanyById`
- Then it merges the DTO onto the existing entity and saves it
- Unknown fields are rejected by the global `ValidationPipe` because `forbidNonWhitelisted: true`
- Empty body handling is not special-cased
- Because the route uses `POST` and does not override the status code, successful updates return `201`

Errors:

- `404` when the company does not exist
- `400` on DTO validation failures

### 5.5 `DELETE /companies/:id`

Soft-deletes a company.

**Request**:

```http
DELETE /api/companies/a3f8c1e2-1234-5678-9abc-def012345678
```

**Response** (`204 No Content`): empty body.

Behavior:

- the service first ensures the company exists via `getCompanyById`
- it then counts rows in the `contacts` table with the same `companyId`
- if any non-deleted contacts remain, the service throws `409 Conflict`
- otherwise the service calls `companyRepo.softDelete(id)` and sets `deletedAt`
- there is no UUID pipe on this route, so malformed ids fall through to the same `404` path as any other missing record

**Conflict response**:

```json
{
  "success": false,
  "code": 409,
  "message": "Cannot delete company with existing contacts.",
  "timestamp": "2026-07-19T00:00:00.000Z",
  "path": "/api/companies/<id>"
}
```

## 6. Error Envelope

All `HttpException` responses are transformed by `src/common/filter/http-exception.filter.ts`:

```json
{
  "success": false,
  "code": 400,
  "message": "first validation or exception message",
  "timestamp": "2026-07-19T00:00:00.000Z",
  "path": "/api/companies"
}
```

Notes:

- `code` is the numeric HTTP status, not a domain error string
- when validation produces multiple messages, only the first message is returned

  @Post()

**Repository** — `src/module/company/company.repository.ts`

```typescript
class CompanyRepository extends BaseRepository<CompanyEntity> {}
```

There is currently no custom repository method for child counting or derived
field assembly; company delete counts related contacts through the repository's
entity manager.

---

## 8. Behavior Summary

- `lastContactedAt` is persisted directly on the company row
- company list sorting is always `createdAt DESC`
- invalid query filter values are ignored rather than rejected
- create returns a wrapper object, while get/update return raw entities
- update also returns `201` because it uses `POST` without overriding the default status
- company delete is a soft delete and is blocked while contacts still exist
