Harness Evaluation 可视化分析

共纳入 12 次 evaluation、4 个 session、241 条约束 finding。最高频规则是 FE-COM-C-002-jsx-max-depth（79 条）；平均 metric coverage 为 96%。

解释优先级：当前所有 evaluation 的 overall status 都是 partial；在比较架构质量前，应先把 metric/adapter error 与真实规则失败分开。

分析框架

1. 测量可靠性

先看 overall/subject status、metric coverage 和 error。回答“结果是否可比”，避免把工具崩溃解释成架构退化。

2. 任务内演化

以 session 为轨迹，观察 T1→T2→T3 的 finding 数变化。回答“持续开发是否累积架构债务”。

3. 实验条件

按 agent × strategy 做描述性比较。当前每个条件只有一个 session，只能观察，不能作因果或显著性结论。

4. 规则与文件热点

规则×evaluation 热图定位系统性违规；文件排名定位反复承载问题的架构边界。

5. 连续指标

不同 metric 单位不可直接相加，因此在每个 metric 内按方向做 0–100 相对劣化归一化；原值保存在 CSV。

6. 性能与完整性

运行时长用于发现 Harness 成本和异常；缺失值保持为缺失，不用 0 填充。
